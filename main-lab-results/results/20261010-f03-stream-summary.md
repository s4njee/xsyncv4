# Raw SSH capacity on neo / freya

Three samples per direction, sequentially after the paired corpus suite. Each
sample transfers exactly 2,147,483,648 memory-generated bytes, with compression
disabled and no file I/O in the timed path. Both processes succeed and the
receiver rejects either truncated or excessive input. The client is neo for
both flows; SSH connection sharing is disabled.

| Flow | Median seconds | Median MB/s | Client CPU seconds | Evidence |
|---|---:|---:|---:|---|
| neo → freya | 18.742 | 114.583 | 6.985 | [JSON](20261010-f03-stream-push.json) |
| freya → neo | 19.054 | 112.706 | 8.817 | [JSON](20261010-f03-stream-pull.json) |

Client CPU includes the Python pipeline and local SSH descendants. Peer helper
CPU is recorded separately in the JSON and excludes sshd. CPU does not represent
the simultaneous total across every process on both endpoints.

The endpoints have a 1 Gb/s link, whose raw bit-rate corresponds to 125 MB/s
before network and protocol overhead. The independently verified baseline
[large-file push](20261010T144748Z-715fa0-large-push.json) takes 18.795 seconds
for the same logical byte count, or 114.267 MB/s. It already reaches the
disk-free stream's measured capacity. There is no measured cipher bottleneck
that justifies multiple SSH streams on this pair. Compression remains opt-in.

[The complete log](20261010-f03-stream.log) retains all samples, and
[load/cache snapshots](20261010-f03-load.json) were captured during the stream
probe. Background load was low on both hosts. The original
[host metadata](20261010T144748Z-715fa0-neo-host.json) and
[negotiated cipher](20261010T144748Z-715fa0-ssh-cipher.json) accompany the paired
suite; the probes use the same SSH options. This observation does not establish
performance on faster links or with another cipher.
