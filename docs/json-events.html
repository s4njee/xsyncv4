xs-json(5) ​

JSON progress events

The --progress=json event stream, field by field, with a published JSON Schema.

SYNOPSIS ​

sh
xs -a --progress=json SRC/ DEST/ 2> events.ndjson

--progress=json writes one JSON object per line to stderr: periodic progress totals, a file record for each transferred regular file, and one final complete record. It produces the same stream on terminals and on pipes, with no cursor escapes. Ordinary stdout (-v, -i, --out-format, --stats) is unaffected.

The stream is described by progress.schema.json ↓ (JSON Schema 2020-12). npm run check validates the published recording, and fresh local, dry-run, checksum and push streams, against it. Every field is listed, and an unlisted field fails the check.

PARSING

Diagnostics also go to stderr, as plain text. Treat only lines that start with { as events. All counters are raw integers that are never scaled by -h. The schema describes the current output and is not versioned; it is not the versioned machine interface planned for the GUI.

RECORDS ​

progress records

Periodic totals, emitted on every display tick.

FieldTypeMeaning
typestringAlways "progress".
elapsed_msintegerMilliseconds since the transfer started.
filesintegerRegular files completed so far.
files_totalintegerRegular files planned so far. Grows while scanning.
bytesintegerLogical file bytes completed. On a push this follows receiver acknowledgments.
bytes_totalintegerLogical file bytes planned so far.
files_seenintegerSource entries discovered by the scan.
wire_bytesintegerBytes sent (push) or received (pull) on the connection, including compression and framing. Zero for local copies.
phasestringWhat the transfer is doing now. One of scanning, transferring, deleting, verifying, waiting for receiver, waiting for sender.
deletedintegerDestination entries deleted.
verifiedintegerSuccessful checksum checks; source and destination hashes each count once.
scanningbooleanTrue while the source scan is still running.
dry_runbooleanTrue for -n; counts describe the plan, and nothing is written.

file records

One transferred regular file (including clones and hard-link members), emitted after the destination operation succeeds, or once per planned file in a dry run.

FieldTypeMeaning
typestringAlways "file".
pathstringTransfer-relative path. Valid UTF-8 is kept; control bytes are JSON-escaped, and invalid bytes appear as the Unicode code points of their byte values.
path_bytes_hexstringThe exact path bytes, hex encoded. Use this when names are not UTF-8.
codestringThe itemize change code, as printed by -i.
sizeintegerFile size in bytes.
bytesintegerFile-content bytes transferred (literal data). Zero for clones and dry runs; only the tail for a resumed file.
dry_runbooleanTrue for -n; counts describe the plan, and nothing is written.

complete records

Final totals, emitted once at the end. Always the last record.

FieldTypeMeaning
typestringAlways "complete".
elapsed_msintegerMilliseconds since the transfer started.
filesintegerRegular files completed so far.
files_totalintegerRegular files planned so far. Grows while scanning.
bytesintegerLogical file bytes completed. On a push this follows receiver acknowledgments.
bytes_totalintegerLogical file bytes planned so far.
files_seenintegerSource entries discovered by the scan.
wire_bytesintegerBytes sent (push) or received (pull) on the connection, including compression and framing. Zero for local copies.
phasestringAlways "complete". Always "complete".
deletedintegerDestination entries deleted.
verifiedintegerSuccessful checksum checks; source and destination hashes each count once.
scanningbooleanTrue while the source scan is still running.
dry_runbooleanTrue for -n; counts describe the plan, and nothing is written.
successbooleanTrue only if the transfer finished with exit status 0.
exit_codeinteger or nullThe process exit status, or null if cleanup began before a fatal status was known.

EXAMPLES ​

The final JSON record of a transfer
sh
xs -a --progress=json src/ dst/ 2>&1 >/dev/null | jq -c 'select(.type == "complete")'
ACTUAL OUTPUT · EXIT 0
{"type":"complete","elapsed_ms":2,"files":5,"files_total":5,"bytes":1289005,"bytes_total":1289005,"files_seen":5,"wire_bytes":0,"phase":"complete","deleted":0,"verified":0,"scanning":false,"dry_run":false,"success":true,"exit_code":0}
Transferred files from JSON events
sh
xs -a --progress=json src/ dst/ 2>&1 >/dev/null | jq -r 'select(.type == "file") | [.code, .size, .path] | @tsv' | sort -k3
ACTUAL OUTPUT · EXIT 0
>f+++++++++	1288895	archive/2026-q3.log
>f+++++++++	33	docs/guide.md
>f+++++++++	42	docs/images/diagram.svg
>f+++++++++	14	notes.txt
>f+++++++++	21	scripts/build.sh
A Python consumer that ignores diagnostics and reports the outcome
sh
xs -a --delete --progress=json src/ dst/ 2> events.ndjson
python3 - events.ndjson <<'PY'
import json, sys
events = [json.loads(line) for line in open(sys.argv[1]) if line.startswith('{')]
files = [e for e in events if e['type'] == 'file']
done = events[-1]
print(f"{len(files)} files, {sum(e['bytes'] for e in files):,} bytes sent")
print(f"deleted {done['deleted']}, exit {done['exit_code']}, success {done['success']}")
PY
ACTUAL OUTPUT · EXIT 0
5 files, 1,289,005 bytes sent
deleted 1, exit 0, success True

BEHAVIOR ​

  • Order. progress and file records interleave as work happens. Once a transfer starts, complete is its last event, even when it fails (for example, "exit_code":25 when --max-delete stops deletions). A failure during setup, such as a missing source or an invalid option, exits before any event is written, so check the process exit status as well.
  • Dry runs. With -n, file records describe planned operations, and dry_run is true throughout.
  • Pushes. bytes follows what the receiver has acknowledged writing, so it can trail wire_bytes.
  • Remote transfers. JSON events need a helper that supports structured file events. If the helper lacks them, or the transfer would otherwise fall back to rsync, xs exits with an error instead, because rsync cannot produce this stream.
  • Suppression. --no-progress or --quiet suppresses the stream. The last progress-mode option on the command line wins.
