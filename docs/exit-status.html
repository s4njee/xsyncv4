xs-exit(7) ​

Exit status & errors

Inspect final status, retained partials, and original diagnostics.

DESCRIPTION ​

A final exit status describes the process outcome. Transfer errors include a bounded summary of the first ten diagnostics, grouped by kind, on stderr. Quiet mode keeps errors visible.

EXIT STATUS ​

CodeMeaningError-summary kind
0Successful operation—
1Syntax or usage errorsyntax or usage
2Protocol incompatibilityprotocol incompatibility
3Input/output selection errorfile selection
4Requested action unsupported, including a peer that lacks a requested feature under --no-fallbackunsupported action
5Failure starting the client/server protocolprotocol startup
11File I/O error, including fatal disk-full errorsfile IO
12Protocol data-stream error, including a remote shell that exits unexpectedlystream IO
13Diagnostic/stdout write failure, including a closed output pipediagnostic IO
14Interprocess communication errorIPC
20SIGINT, SIGTERM, or SIGHUPinterruption
23Some files or attributes were not transferredpartial transfer
24Source files vanished before transfervanished source files
25Deletion limit exceededdeletion limit
30Remote idle I/O timeoutidle timeout
127Remote helper not found, with fallback disabled, or the remote shell command could not be runremote command not found
255The remote shell itself failed (for example, ssh could not connect); its status is passed throughremote shell failure

Code 124 is defined for rsync compatibility but xs does not currently return it.

MISSING SOURCE ​

Command from the actual error recording
sh
xs -aP ./missing-source/ ./unused-backup/
ACTUAL XSYNC DIAGNOSTIC / EXIT 23
xs: link_stat "./missing-source/" failed: No such file or directory (2)
xs: error summary: 1 error (showing first 1)
  partial transfer (code 23): 1 error
    link_stat "./missing-source/" failed: No such file or directory (2)
xs error: some files/attrs were not transferred (see previous errors) (code 23)

INTERRUPTION AND RETRY ​

Ctrl-C interrupts a run with exit code 20. With -P, completed contiguous partial data can be retained. Rerun the same transfer to verify and reuse matching prefixes.

Retry a partial transfer
sh
xs -aP src/ dst/

A completed-byte prefix can be reused only when it matches the source. Transfers do not invoke fallback after an active copy has failed.

SCRIPT EXAMPLE ​

Preserve the command’s original exit status
sh
if xs -a --no-progress src/ dst/; then
  echo "transfer completed"
else
  status=$?
  echo "xs failed with code $status" >&2
  exit "$status"
fi

An exit-23 result may include successful files and failed files in the same run. Inspect the diagnostics rather than assuming the entire destination was rolled back.
