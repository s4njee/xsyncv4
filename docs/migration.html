xs-from-rsync(7) ​

Coming from rsync

What stays the same, what changes, and how to switch an existing rsync habit or script to xs.

THE SHORT VERSION ​

xs takes rsync’s command line. Trailing-slash rules, -a, filters, --delete, itemized output and exit codes all mean what they mean in rsync. Options it does not implement are handed to a real rsync automatically, so an existing command keeps working. You need xs on both machines for native remote transfers; without it, those transfers fall back to rsync too.

Try it on one command before changing anything else
sh
xs -ani --delete src/ dst/      # preview: same itemize codes as rsync
xs -aP src/ dst/                # then run it
ALIAS

alias rsync=xs works for interactive use. In scripts, call xs by name instead, so it is clear which tool ran and fallback stays visible. Fallback runs whichever rsync is first on PATH. An alias does not change that, because aliases do not apply to the executed program.

YOUR COMMANDS ​

These are the invocation shapes xs was built around, taken from real shell history and project scripts.

If you runWith xs
rsync -axhP DIR DESTWorks as is. -x stays on one filesystem; -P resumes interrupted files from a verified prefix; progress is xs’s live display. -h uses decimal units, -hh binary.
rsync -az[P] SRC DEST, with --excludeWorks as is, locally or over ssh. -z uses zstd; filters keep rsync’s first-match rules.
rsync -e "ssh -i KEY" …Works as is. Quoting in -e, keys and passphrase prompts behave as with rsync.
rsync -az --delete --out-format='%i %n' in a scriptWorks, with stable output: file lines are sorted when stdout is not a terminal. %b counts file bytes rather than protocol bytes.
rsync -rlptz, --info=progress2Works. --info=progress2 prints rsync’s line shape on a pipe; --progress=json is the structured alternative.

The compatibility page lists the details, and delegated options lists exactly which options go to rsync.

SWITCHING A SCRIPT ​

  1. Replace rsync with xs and run the script once with -n added. Compare the itemized output with rsync’s; it uses the same codes (itemize reference).
  2. Look for xs: falling back to rsync: on stderr. Each notice names the option or condition that caused it.
  3. Decide whether fallback is acceptable. If the script must be native, add --no-fallback or set XSYNC_FALLBACK=0; it then fails before writing instead of silently running rsync.
  4. Pin personal defaults out of the script’s way with XSYNC_CONFIG='' XSYNC_OPTS='' if your interactive defaults should not apply (control defaults explicitly).
  5. Keep checking the exit status. The codes are rsync’s: 23 for a partial transfer, 24 for vanished files, 25 for the deletion limit, and so on (exit status).

SPEED EXPECTATIONS ​

xs is built for trees of many small files and for local copies on one APFS volume, where clones and parallel workers help most. Over a 1 Gb/s network, uncompressed transfers are limited by the link, and both tools take about the same time; -z helps xs more. Some cases are slower today. See performance for measured numbers, losses included.
