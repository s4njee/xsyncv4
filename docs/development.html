Development status

Current capabilities and remaining work, generated from the project backlog.

SCOPE ​

Tier status and open items below are generated from the tier tables in backlog.md on every build. Curated text was last reviewed on 2026-10-10 against the README and executable help. Earlier backlog problem statements are historical; each item’s latest status describes the implemented CLI.

NOTE

This page describes development status. Planned capabilities are not part of the command reference.

GUI ENGINE ROADMAP ​

EXTERNAL

This roadmap comes from a GUI backlog maintained outside this repository. It is not checked by this build; statuses are as of the 10 October 2026 review.

All GUI backlog stories G-01–G-24 are open. Existing copy, listing, selection, metadata, and progress primitives are foundations for these requirements, rather than evidence that the full GUI contract exists.

PriorityProposed work
P0 · G-01–G-08Versioned machine interface, deterministic execution, structured browsing, authoritative completion, typed per-item errors, headless SSH auth, conflict decisions, job cancellation
P1 · G-09–G-18Rename/move/delete workflows, private partials, persistent queue/recovery, previews, responsive browsing, preflight/refresh, aggregate controls, helper lifecycle, acceptance client
P2 · G-19–G-24Remote-to-remote copies, additional endpoint adapters, Windows support, large-directory budgets, preview/edit, optional embedded library

CURRENT BOUNDARIES ​

Two-pane browsing does not imply automatic bidirectional synchronization. Persistent queues, interactive conflict choices, job-control APIs, and runtime aggregate limits remain proposed GUI integration work. Current --progress=json is documented on the output page; it is not a promise of that future versioned GUI API.

MAINTENANCE ​

The option reference and downloadable manpage are generated from xs --help. Exit codes come from the RERR_* definitions in the source, and tier status from backlog.md. Workflow pages are curated from README behavior.

Source fingerprints for the curated pages are in sources.json; npm run check fails when a fingerprinted source has changed since review.
